# 20261022 实验思路：稀疏读集、真实驻留与按需预取收敛

## 1. 定位与结论

本文记录 2026-10-22 当前工作区的代码核对结论和待实施思路，不代表下述优化已经实现或通过验收。本轮只新增本文，不修改功能代码。

项目核心目标以 `../../GranuleKV/KV_SPARSE_PREFETCH_CORE_LOGIC.md` 为准；本文不替代或修改该文档，也不修改原有 1008 汇报。

主线保持为：已有完整 KV 写入 SSD；首批稀疏工作集直达 GPU，其余数据后台进入固定 CPU backing；后续逐层只传输所需且尚未有效驻留、也没有可复用在途传输的 KV。CPU backing 是完整数据来源，不意味着每次向 GPU 恢复完整历史。

当前最重要的结论：

- 32 KiB `[K block | V block]` descriptor 合并只减少 descriptor 数，不减少相同读集的 KV 字节数；布局变化不应改变选择、驻留或调度语义。
- 大量 H2D 不全是重复提交同一 mapping。历史 suffix 被全部必选，加上跨层共享物理 region，形成反复换入换出；这是结构性流量。
- 当前有 GPU owner 校验和异步 copy 基础，但不能据此宣称已经实现固定 sink 常驻或真实提前预取重叠。
- 用户提出的“先预测，再保留 GPU 上仍需使用的 KV，只搬缺失部分”方向成立，前提是真实物理位置保得住，且实际 Query 选择仍负责最终结果。
- 首先统一读集与 backing 来源，然后解决物理驻留边界，再利用已有预测提前提交；不要叠加新预测器、通用 allocator 或第二套恢复状态机。

## 3. 统一历史 KV 的选择范围

### 3.1 先区分两个边界

immutable prefix 是跨请求复用、已有 SSD mapping 的范围；可参与稀疏选择的历史是当前请求已经计算完成的历史。二者不能继续使用同一个长度概念。

设当前 chunk 开始前已计算 `computed` 个 token，block size 为 B：

- 历史完整 block 范围为 `[0, floor(computed / B))`；其中可以包含原 cached prefix 和已经形成的 suffix。
- init/sink 与必要 local history 是必选集合，local 以当前已计算历史的末端为边界。
- 其余有有效 representative 的历史完整 block 进入已有 scoring、每头 top-k 和 head union。
- 未填满的旧 partial tail、当前 chunk 新 KV 仍按现有因果计算保护，不因稀疏化丢失，也不从旧 CPU 副本重读当前 chunk。
- “历史 block 完整”不代表“已有 SSD 副本”；CPU backing 和 SSD 可恢复范围仍分别判断。

### 3.2 在已有函数中收敛

1. 在 `SolidAttentionPolicy` 内推广已有历史选择入口，继续复用 `_score_pages()`、稳定 top-k、固定容量索引和控制 buffer。明确 immutable storage boundary 与 selectable history boundary，不另建 selector。
2. 调整 `select_actual_blocks_device()`，由它产出唯一最终读集；不再无条件拼接全部历史 suffix。现有 `SparseKVActualSelection` / device selection 类型优先复用；如果保留 `prefix_blocks` 字段名，必须保持其原有含义，不偷偷装入生成历史。
3. `_correct_hierarchical_layer()` 使用该读集统一判断 GPU hit 和 pending，再按已有数据来源恢复缺失：原 SSD-backed prefix 使用现有 correction mapping，生成历史使用固定 host backing。
4. `_restore_live_backing()` 对 prefill 和 decode 都只做 Query/QKV 写入前不可推迟的 partial-tail 与物理 fence 保护；普通历史恢复放到实际 Query 选择之后。
5. `_restore_backing_blocks()` 继续负责传入集合中的 host missing，不增加另一套 suffix copy。移除被唯一读集替代的整段历史恢复和第二次集合拼接。
6. XFormers 继续复用当前稀疏 prefill workspace 和 selected-list decode。历史按逻辑顺序组织，mixed partial block 按有效历史 token 截断，当前 chunk 只加入一次；保留原始 RoPE 位置和 bottom-right causal 关系。

### 3.3 必须同时补齐的 metadata 生命周期

`_cached_representatives()` 已有增量构建逻辑，但不能在旧层 slot 被覆盖后回头扫描历史 K 来补 metadata。现有 page-key metadata 还可能被多个复用同一 prefix 的请求共享，不能直接往其中追加请求私有 suffix。

最小方向是在 layer release/backing 边界、该层新 K 仍有效时，为本轮新封满的 block 增量生成 representative；沿用现有 builder 和 request/layer metadata 容器。跨 chunk partial block 只在封满后加入候选。prefix 共享 metadata 保持不变，请求私有增量随 `discard()` 清理。

在同一 compute stream 上先完成写入、metadata 生成，再记录保护 slot 的 release event；不为提取 metadata 增加 CPU 同步。索引缓存随候选增长失效，不能错误复用旧长度下的 fixed/candidate 张量。

`hierarchical_io/residency.py::prediction_state()` 和 correction catalog 当前只覆盖 immutable prefix。不要简单扩大 `num_prefix_blocks`，否则会把没有 SSD 地址的生成历史交给 SSD correction。必要的语义调整应集中在现有 selection、gap 校验和 host 恢复接口，不扩展 native 协议。

选择范围扩大属于算法近似范围变化，必须单独做质量门禁，不能当成纯搬运优化直接宣称无损。

## 4. 固定驻留与轮换空间的物理边界

当前 8-region 映射会使 layer 0/8/16/24 的相同 destination 指向同一物理 slot。即使 sink 永远被选中，其他层的写入也可能覆盖它。`_back_up_layer()` 不等于主动逐出；真正失去驻留通常发生于新 owner 覆盖 slot。

目标分为两个层次：

- 固定 sink：在既有总 GPU 字节预算内，保留每层互不覆盖的位置，不参与动态轮换。
- local 与动态预测命中：保护当前必需数据，按后续需求尽量保留；local 会滚动变化，不把全量 suffix 解释成必须永久常驻。

最小实现审查应从现有 allocation、block table 与 slot mapping 开始，先确定能否使用同一底层分配中的静态分区，避免新增通用 allocator。无论采用什么映射，SSD destination、H2D/D2H mapping、QKV writer 的 slot mapping、Attention block table 和 owner key 必须一致。

当前共享 layer tensor 和常规 block table 不自动提供这种每层隔离。不能只改 `_gpu_slot_key()`，也不能让 host owner 掩盖物理覆盖。若需要大范围重写 writer、Attention 或引入第二套地址解析，停止并单独报告，不把复杂映射隐藏在本轮优化中。

固定驻留会占用原有轮换空间，必须同时核算最坏情况下 head union、local、当前 chunk 和在途目标是否还能放下。预算不足要明确报告，不暗中加大 GPU cache，也不承诺所有预测命中都能跨完整层循环保留。

## 5. 复用已有预测：命中保留与缺失预取

继续用 `observe_query()` / `predict_restore_blocks()`，不增加新预测器。单 Query 已有 actual feedback 复用；多 Query chunk 当前不走相同的 feedback 快捷分支，需要沿现有观察接口明确复用语义，不重新执行一遍完整 scoring 来构造第二份选择。

每次提前提交和实际消费都遵循同一计算：

```text
需要提交的块 = 需求集合 - 有效 GPU hits - 同 owner/目标/版本的 pending transfers
```

预测集合只决定提前搬什么、替换时尽量留下什么；实际集合仍由当前 Query 生成。预测错误只产生性能损失，不能改变 Attention 结果。

具体复用位置：

1. 在现有 forward 边界固定本轮可用的同层历史预测，冷启动继续使用已有初始 plan，不另造预测来源。
2. 在 `_release_hierarchical_layer()` 的现有 callback 中尝试推进下一层已 READY 的 host 数据；不等待未知 prediction，不在 speculative 路径新建 SSD correction。
3. 将 worker 的 `copy_host_blocks_to_gpu_async()` 收束为提交与消费两个职责：底层 CacheEngine 已返回 event，worker 提交时登记现有 pending 表，消费时仅对实际使用的 event 执行 compute `wait_event()`。
4. actual correction 与提前提交共用这一 helper。pending 命中不能仅凭“表里存在”就当作完成；必须匹配 owner/目标，消费方依赖 ready event，再按现有语义发布 owner。
5. 只在真实可保留的物理 slot 上实现预测保留。当前映射若必然覆盖，则承认不能命中，不加 metadata 假保留。

finish/abort 复用 `_forget_host_staging()` 和 policy `discard()`；generation rewind 继续显式拒绝，不扩展 epoch 状态机。

## 6. 按 Tutti 原则安排写回

### 6.1 保留已有正确性约束

`_back_up_layer()` 的 dirty 范围、已有 host 副本判断、release/backup fence 必须保留。首窗 GPU-only immutable 数据仅补缺失 CPU 副本，已有 SSD source 不重复写 SSD。新 dirty KV 必须在唯一 GPU 副本被覆盖前获得可靠 backing。

CPU backing READY 由 `_poll_gpu_to_host_backing()` 的 event 完成确认；同一 copy stream 上的依赖复用不能变成提前向 SSD WRITE 发布 host READY。

### 6.2 最小调度调整

- 继续使用唯一固定 copy stream 和既有 `swap_blocks()`，不另建 copy 实现。
- 在目标 slot 及依赖允许的情况下，先排下一层 H2D，再排当前层等待 release 的 D2H，避免同一 stream 的队首 D2H 等待挡住预取。
- 若下一层目标复用的正是当前层 dirty slot，必要 D2H 就是覆盖前置条件，不能为“读优先”删除这个依赖或强行交换顺序。
- CPU 到 SSD 沿用现有 WRITE request、reservation 与 deferred 表；在现有提交/推进位置优先推进必要 READ，再提交 host 已 READY 的完整 block 写回，不新增常驻调度线程。
- `_deferred_gpu_transfers` 目前包含 backing/fence 等待，不等于已实现带宽优先级。需要区分“因依赖不能提交”与“为关键读延后提交”，但不建立第二份写回队列。
- 已提交的 native WRITE 不能假定能抢占或取消；读优先主要在提交前实施。尾部排空单独计时，不能把写回延后当成总耗时减少。
- 不完整 tail 只保留 backing，不发布成 immutable SSD prefix；写完成后才发布可复用 metadata，沿用现有 finish/abort 生命周期。

Tutti 本机论文第 3.3 节强调关键读优先、按 slack 延迟写，并指出无条件 SSD 读写并发会争用。借鉴这个原则，不移植其 GPU io_uring、green context 或离线调度表。仓库的 SGEMM 逐层示例不是当前真实稀疏推理已重叠的证明。

## 7. 实施次序与验收

1. 先在已有 policy 测试中验证完整历史候选、增量 metadata、local 边界、稳定排序和 chunk=1 一致性，再替换 worker 的整段 suffix 恢复。
2. all-block 必须与 Dense 对齐；固定选择下 resident、SSD 到 GPU、SSD 到 host 到 GPU、共享 region 的 KV/Attention/logits/token 必须对齐。覆盖 partial tail、跨 chunk 封块和第二个输出 token。
3. 真实稀疏选择用 cached-prefix 加多 chunk suffix 的质量生命周期验证，不能用未经过新路径的普通 resident runner 代替。沿用原 Passkey/LongBench 门禁。
4. 单独确认固定驻留映射可局部实现后再推进；不能以放松物理 owner 校验取得 hit。若阻塞，报告映射约束，保留已独立验收的读集收敛成果。
5. 在稳定读集上增加已有预测的提前提交，验证 pending 去重、实际消费 event、slot 覆盖和清理；随后评估写回提交顺序。
6. 主性能口径固定 1008/Tutti 的 `output=2`：首输出看 TTFT，第二输出看首次 decode 间隔。先测 16K/16K 与 32K/0，再扩展六个 prefix；保留 RoPE 修正，统一容量、冷/热状态和排空边界。

最小证据包括实际 H2D/D2H/SSD 字节、同等 layer-block 的 descriptor 数、必要读集外预取量、真实 prediction recall、Selection 控制等待、GPU hit 和生成/排空耗时。用匹配 request/layer/step 的时间线确认 overlap，profiling 样本不进入正式性能统计。

执行错误、stale owner、host coverage missing 和重复 SSD 读取必须为 0；同一 block 因真实容量替换后再次必要 H2D，要与重复提交同一个 pending copy 区分。性能路径不新增全局同步或 CPU event synchronize，不承诺所有 Selection 控制依赖均为零。

若质量下降、地址映射需要大改，或增加的预测流量没有净耗时收益，停在对应阶段解释原因，不增加 fallback、全量恢复或更大 cache 绕过。

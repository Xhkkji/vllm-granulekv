## 旧版128K核心失败定位

`old_fixed128k_cold/` 已通过两token门禁，顺序A/B分别251.903/265.861秒；随后同时提交在A31、B32个输出时失败。调用链是 `_correct_hierarchical_layer_one → _correct_bounded_history → _reserve_gpu_slots`，报 `no safely reusable GPU KV slot for actual selection`。

`failure_lifecycle.json` 和 `old128_failure_analysis.json` 显示第5层：

- 2135个物理slot全部占用；A/B逻辑映射分别2118/2130项，最后记录的需求分别455/430项。
- 2129个共享副本中，2113个有两个消费者；1560个不在两请求最后记录的需求中，且GPU READY、CPU本层backing READY，其中1558个仍有双消费者引用。
- 旧版只检查当前请求的回收候选，遇到 `shared.references - {request_id}` 就跳过。A/B曾经共享、现在暂不需要的绑定持续保留，导致后续新需求预留失败。

这些需求不是同一时刻重新计算的整批并集，快照也没有DMA/fence完成查询结果，不能说1560个slot当时都可立即复用。证据确认的是旧引用阻断了候选进入后续安全检查。新版已有整批需求登记、容量不足时安全解绑共同不需的副本；本轮未再改它。

按停止条件不修旧版、不执行其128K热态、不用失败样本计算batch跨版本加速比。新版性能回退也未用叠加生产优化掩盖；剩余长数值诊断未继续扩展。

## 写回诊断与实现对照

35K冷态独立诊断（不计入性能）：实际PagedAttention调用14308次＝511次单query forward×28层；另一次多token prefill保留原路径。source引用获取/释放各50824次，结束无剩余引用。H2D共50824个层块、9276次提交；D2H14336次提交。dirty D2H为673447936字节，而新增/重算有效KV为61415424字节，约10.97倍；immutable backing另33030144字节。SSD读2022178816字节/7次、写60555264字节/2次，不能把每步D2H称为每步SSD写。

308个Attention API GPU事件区间p50为0.125毫秒；618个现有slot复用fence区间p50约0.0053毫秒，包含event/enqueue开销。它们是采样值，stream可重叠，不能相加解释全部服务时间。

- [Tutti论文](https://arxiv.org/html/2605.03375)：读优先，将写安排到可用计算间隙，依赖stream/event保护；其H100、多SSD、到达负载不能与本机V100结果直接比较。
- 本地Tutti connector `integration/vllm-connector/adapter/connector.py:205` 以已保存前缀跳过旧chunk，仅保存新增完整chunk（默认256 token）；`engine/core.py:255` 排除stored/pending，完成后发布。存储LRU不是GPU物理槽位回收，不能直接移植替代本系统安全回收。
- [SolidAttention FAST26](https://www.usenix.org/system/files/fast26-zheng.pdf)：batch1、最大输出512，硬件和权重精度不同；新KV先至DRAM，再用每层32KiB写缓冲聚合SSD写。本文借鉴输出尺度，不声称论文复现。
- 当前 `vllm/worker/worker.py:_back_up_layer` 每步dirty完整16-token block建立CPU backing，immutable已有backing可复用；容量不足时安全回收；`vllm/core/async_kv_scheduler.py:_try_start_granulekv_prefix_store` 在完成路径保存完整prefix到SSD。

下一步最小定位应先比较新版/旧版顺序decode的同口径CPU profile，区分 `_back_up_layer` 对resident/consumed/predicted的候选分类与 `_poll_host_cache_uses` 对保留H2D记录的扫描，不能把全部回退直接归因于写放大。dirty整块重复复制已有字节证据；若后续要改粒度/时机，必须先确定部分尾块恢复、四层区域复用及fence的安全边界。本轮只交付位置和证据，不新增写回框架或调度策略。

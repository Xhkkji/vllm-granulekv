工作主要内容
夏寒柯
1、稀疏 KV 通用复现能力建设。
	围绕 Quest 与 SolidAttention 建立了统一的稀疏 KV 接口，分离逻辑 Block、物理 Block、驻留状态和 Attention Working Set，并保留 Dense、Compact 和原有 GranuleKV 路径作为对照。
2、SolidAttention resident-only 路径复现。
	完成 Init、Local、Selected 三类 Block 的组合选择，将 GPU 侧代表向量评分和 selected logical block list 接入实际 Attention，8K、Batch Size 1 场景下 Selected Block 比例约为 36%，性能与 Dense 基本同量级。
3、动态预测恢复与 correction 链路。
	完成 Prediction、Actual Selection、Physical Residency 三类集合的区分，支持预测 Block 的 GranuleKV 异步恢复和当前层缺失 Block 的 correction，并增加 prediction recall、miss、补读量、等待时间等统计。
4、SolidAttention Attention 接口与策略优化。
	增加 selected-list Attention kernel 接口，完成滑动窗口内的选择结果复用和动态路径的 selected-list 调用，减少不必要的 Compact 路径转换，为后续预测预取和 correction 合并保留实验入口。
5、GranuleKV I/O 与请求生命周期验证。
	整理 GranuleKV Client、Connector、Executor 和异步请求生命周期，验证 SSD 到 GPU、SSD 到 CPU 以及 GPU/CPU 混合直传。大批量 Submit 测试表明，16KB I/O 在约 896 descriptors/submit 时带宽已接近稳定，混合目标未观察到明显的额外带宽损失。
6、端到端性能分析与瓶颈定位。
	对 Dense、resident-only 和动态 SSD 路径进行对照，确认动态路径的主要损耗来自大量逐层同步 correction、补读等待和 Actual Selection 控制开销，而不是 SSD 总读取量或 selected Attention kernel 本身。

未来工作计划
夏寒柯
当前主要问题是动态稀疏路径中预测漏块被放大为大量同步 correction 请求，补读无法与后续 GPU 计算充分重叠，同时逐层 Actual Selection 和 CPU 控制路径仍有额外开销。后续计划优先在 vLLM 调度层探索更粗粒度的预测预取和 correction 合并，利用 GPU 当前所需 Block 直传 GPU、其余可复用 Block 直传 pinned CPU 的方式减少重复 SSD 读取，并在后续 miss 中优先复用 CPU 缓存。实现阶段保持 GranuleKV native、MPS service、descriptor pool 和原有接口不变，先通过独立实验验证收益，再接入正式 SolidAttention 动态路径；同时继续完善端到端时间拆分和正式质量测试。

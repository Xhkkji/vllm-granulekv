## 实现范围

- 新增默认关闭的 `VLLM_GRANULEKV_HOST_BACKING_ENABLE`；要求单请求、单步调度、固定 pinned host cache 和已有异步 copy stream。
- 首窗 GPU-only KV 和本轮新计算 KV 在 layer release 后，通过同一 copy stream 异步备份到固定 CPU region。host backing 只在对应 event 完成后发布 READY。
- H2D/D2H 复用现有 `swap_blocks()`；物理 slot 的下一次覆盖受 release/backup event 保护。native SSD read 的覆盖只在 query READY 后提交，不增加 CUDA 全局同步。
- 复用现有 prefix-store reservation，在请求完成后提交完整且已计算 block 的 host→SSD WRITE；所有 layer 完成后才提交 storage metadata。partial tail 不写 SSD，已有 immutable SSD block 不重复写入。
- GranuleKV 控制层只解除 host WRITE 限制；native、wire protocol、descriptor pool、MPS service、CUDA IPC 不变。
- 单 token prefix-prefill 复用 selected-list kernel 和原有 Actual Selection；多 token suffix-prefill 仍保留原有完整上下文读取。
- 初始化检查 CPU 容量覆盖模型配置的最大请求长度，运行时检查 prompt+output 容量；关闭时若 CUDA copy 未完成则拒绝注销 pinned memory。
- 修复 finish 清理 set 时的迭代删除错误，以及尚未 forward 就 abort 时的 metadata 清理。

## 新定位到的测试配置问题

模型原始 `max_position_embeddings=32768`。仅设置 runner 的 `max_model_len=33792` 并允许超长，并不会扩大 Qwen2 的 RoPE lookup table。

32768-token prompt 后的 decode 从 position=32768 开始，超出了原始位置表。诊断中首个新 token 的 V 一致而 K 出现异常大值；将 Dense/resident/restore 的 runner 统一使用 `hf_overrides={"max_position_embeddings":33792}` 后，固定 selection 的 K/V、Attention、logits 和 token 全部对齐。

该修改只扩大未缩放 Qwen2 的位置表，不修改 RoPE 频率、不修改模型文件。trace 记录并校验位置表长度，旧 trace 不可混用。旧配置下的 32K 连续 decode 结果必须重测，不能沿用其性能结论。

## 已完成的 GPU 验证

模型 Qwen2.5-7B-Instruct，FP16，batch=1，block=16，GPU blocks=2304。

| 验证 | GPU region | Output | 检查数 | 结果 |
| --- | ---: | ---: | ---: | --- |
| all-block selected-list 对同 KV 的 Dense paged reference | 28 | 2 | 56 | Attention 误差 0 |
| resident record → host backing 固定 selection replay | 8 | 8 | 224 | KV/Attention/logits mismatch 均 0，8 个 token 完全一致 |
| all-block 连续 decode + 完整新 block SSD read-back | 8 | 64 | 1792 | Attention 误差 0；84 个 layer-block 读回逐字节一致 |
| populate 建立真实 metadata 后，validation=off 的 Actual Selection smoke | 8 | 8 | 224 次 selected-list 调用 | Compact=0；错误计数均 0 |

固定 replay：D2H 提交 224 次，备份 364 个 layer-block；live backing 命中 168 次。

正常 Actual Selection smoke：GPU hit=18,084，host hit=38,808，D2H=364 个 layer-block；8 个 token 与上述参考一致。单次 smoke 的 TTFT=1330.52 ms、TPOT=263.92 ms、elapsed=3177.97 ms，不作为相对 Dense 的性能结论。未做单独 Dense 采样，也未满足正式 warmup/repetition 口径。

Output=64：共备份 1932 个 layer-block、60.375 MiB；新增 SSD write 为 3 个跨层完整 block，共 2.625 MiB。每个完整 block 检查 28 层，合计 84 个 layer-block；剩余 15-token partial tail 不写 SSD，最终 write backlog 为 0。

上述共享 region 验证中 `correction_errors`、`duplicate_ssd_read_blocks`、`host_coverage_missing_blocks`、`stale_gpu_owner_hits`、`legacy_device_synchronize_count` 和 `selection_tolist_calls` 均为 0。

注意：all-block 的逐层 Dense reference 使用同一份 KV，单独通过并不能证明恢复数据正确；恢复数据正确性的证据是独立 resident 记录与共享 region 固定 selection replay 的对齐。

## 运行与边界

```bash
# 已有 SSD 数据时的 all-block 验证；默认不做性能测试
env RUN_DIR=/absolute/result/path OUTPUT_TOKENS=64 HOST_WRITE_READBACK=1 \
  bash GranuleKV/vllm_evaluation/tutti_layerwise/run_host_backing_validation.sh

# 正常 Actual Selection 必须先建立 representative metadata。
# static plan 只提供初始 restore prediction，不替代当前 query 的 Actual Selection。
env RUN_DIR=/absolute/result/path SKIP_POPULATE=0 \
  VLLM_GRANULEKV_TRUST_PREPOPULATED_PREFIX=0 \
  SPARSE_VALIDATION_MODE=off OUTPUT_TOKENS=8 \
  bash GranuleKV/vllm_evaluation/tutti_layerwise/run_host_backing_validation.sh
```

尚未完成全部性能门禁，不能宣称无性能回退或优于 Dense：

- Nsight 在现有 MPS 环境中的一次采样停滞并产生错误，未取得可用的完整 overlap 时间线；独立 stream 不是 overlap 的验收证据。
- 尚未完成六个 prefix 的 TTFT/TPOT 正式 3 次 warmup、10 次采样，也未证明写回对性能无回退。
- 目前使用 request identity 和最新 pending backup event 隔离版本，检测到 request rewind 显式失败；不支持抢占后复用同 request 的 generation 迁移，不能宣称通用 generation 生命周期已完成。
- 复用既有 GPU physical-owner residency；未引入新的 keep predictor，未证明 keep 命中率及 H2D 流量获得改善。
- 固定 selection 已通过组合恢复路径，尚未分别完成所有独立数据路径及六个 prefix 的完整矩阵；output=64 的跨路径固定 replay 仍需补测。

新开关保持默认关闭。validation 快照、Dense reference 和 SSD read-back 只在验证进程启用，不计入性能样本。

## 已完成的验证与修正

- 验证快照改为 pinned buffer 的异步 D2H，请求结束后仅 query 完成事件，再在 CPU 上计算 fingerprint 和误差；不增加逐层 CUDA synchronize。
- 验证关闭时不分配快照或安装 logits hook；验证结果不写入性能 CSV。旧的逐 step 同步计时 hook 改为显式 `--sync-compute-profile` 启用。
- resident 参考也先准备 prefix 并命中 GPU cache，与 SSD restore 保持相同的最后一个 prompt token 重算流程。
- fingerprint 排除 live block 的未使用槽，记录边界 token、物理 block、page identity、attention output 和 decode logits。
- replay 比较真正消费的固定 selection，不要求自然重选结果也相同；动态 replay 不依赖重新 scoring 或 representatives。
- owner 和 release event 的键改为真实物理 slot：`(virtual_engine, layer % num_gpu_regions, destination_block)`。逻辑 residency 仍区分 request、layer 和 logical block。
- 空验证、没有 decode attention、缺少 replay 和执行异常不能获得通过结论。

## 已证实的问题

### 1. 物理 region 已覆盖，旧 residency 却仍命中

working-set 配置只有 8 个 GPU region，layer 0/8/16/24 共享 region 0。原 owner/event 键使用逻辑 layer，不能识别这些物理别名。

修正前的第二次 decode 中，layer 0 的 276 个被检查的非边界 block **全部匹配上一轮 layer 24 的 KV**；layer 1 的 296 个 block 全部匹配 layer 25。不是简单的 Sparse 近似误差。

### 2. 首窗 GPU 直读的数据没有 host 副本

原始划分将首窗 36 个 block 直接读入 GPU，host 只读取它们的补集；其他层通过 host tail request 覆盖。首窗这些 block 被后续层覆盖后，下一次消费不能再依赖 GPU hit，也没有对应 host backing。

修正物理 owner 后，第二次 decode 的 layer 0 明确报出缺失：`0..33, 2046, 2047`。没有通过增加重复 SSD 读取或新的 fallback 掩盖该缺口。

### 3. Prefill 与 mutable tail 仍需闭环

host 路径在首次 decode 之前产生的 token 已与参考不同。当前 correction 仅处理 decode，prefix-prefill fallback 仍按完整 context gather KV；必须检查稀疏恢复是否覆盖了它实际读取的数据。

此外，各层 GPU tensor 整体按 region 取模共享，last-prompt-token 重算和新生成 token 的 mutable KV 也需验证是否有独立的逐层保存位置。这部分不能用 immutable SSD prefix 代替，尚未完成修复与验收。

# GranuleKV 异步预取收敛验证

## 第一阶段

实现前已分别提交并 push checkpoint，保持原分支不变：

- vLLM：`32939f99b1bb12e2be6c4e6f5a7ea735726674ba`
- GranuleKV：`757007bd08f019ca501f979a05b52140aa67a19f`

本阶段没有移动 H2D 提交点，没有增加开关、fallback、缓存分配器或同步点，也没有修改 native 协议及原 1008 汇报。

| 调整 | 实现范围 |
| --- | --- |
| SSD 字节统计 | 按实际 layer range 计数，另报 layer-block；32K 完整恢复合计 1.75 GiB，与 mapping 对应字节一致 |
| 预测统计 | recall 使用 predicted 与 actual 的交集；prediction miss 与恢复后的 resident coverage 分开，不改变 correction 判定 |
| 等待统计 | 未实现的 event 等待时长为 unavailable；legacy 全局同步计数不代表所有 CUDA 隐式同步 |
| Selection | 缓存 candidate/logical 索引；异步 Actual Selection 使用固定容量有序索引与尾部哨兵，在原有 CPU mapping 依赖处读取有效列表 |
| Feedback | 同 Query、metadata、budget 且 guard=0 时复用 Actual Selection；其他配置保持原 predictor |
| 计时 | 区分最后一个输出 token 到达与请求写回排空，分别报告生成和包含排空的耗时 |

## 测试准备问题

1. 结束的 populate 请求局部 metadata 已清理，runner 改为通过稳定 page identity 发布短前缀 metadata。
2. `max_tokens=64` 原来允许 EOS 提前结束，性能测试现固定输出长度。
3. 准备阶段原来生成 64 token，resident prefix cache 会留下完整 generated blocks。step=16 时 reference 的 logical block 2048 从 physical 2051 替换为 2048，前 15 个已计算 token 的 KV 发生变化。checkpoint 与第一阶段对这份污染 trace 的失败位置及差异计数完全一致，不能归因为本轮 Selection 改动或 CPU Cache 损坏。
4. 准备统一只生成建立 metadata 必需的 2 token，不留下可复用的完整 generated block；重建 reference 后，64-token 严格回放完全对齐。不修改生产分配器或 backing 逻辑来掩盖测试问题。

## 第二阶段试验

第一阶段已独立提交并推送：vLLM `5feb2913e5cc29806e90d9a5af10629a327a45de`；GranuleKV `3759e89a43dfeaf95e71a46b6fe61aa89eb76914`。

第二阶段只调整现有 Python 提交点：在当前层 release callback 中，先尝试提交下一层已 READY 的 immutable prediction，再提交当前层 D2H backing。按需 correction 和预取共用同一个 H2D helper；helper 返回 ready event，Actual Selection 的消费者才在 compute stream 等待实际使用的 pending event。

已有 feedback 在 forward 结束时更新本地 plan 的 prediction，不修改 selected list。预取跳过未 READY host、已有 GPU/pending、native 同目标 transfer 和未完成 release/backup fence。未消费预取继续保留 copy fence，不能用更早的 compute release event 覆盖。没有新开关、预测器、allocator、生命周期表或正常路径 CPU 同步。

| 测试 | 结果 |
| --- | --- |
| 相关 CPU/GPU 单测 | 135 passed；包括提交不立即等待、实际消费 event 去重、pending 去重、物理 fence、feedback identity 与清理 |
| Runner 配置与统计单测 | 9 passed |
| 32K/0 all-block，output=1 | 28 次检查，逐层 Dense reference 误差 0，首 token 323，Compact 0 |
| 32K/0 固定 selection，output=64 | 1792 次检查；KV、Attention、logits mismatch 全 0；64 个 token 与 resident reference 完全相同 |

64-token 验证样本中预取 244443 layer-block，实际消费 194772，未消费 49671（约 1.516 GiB）；总 H2D 为 12658802688 bytes。该样本开启 validation，只证明正确性与流量，不能作为性能数据；GPU hit 增多也不等于专门 prediction keep 优化的收益。

结果目录：`stage2_allblocks_o1`、`stage2_host_clean64`。保持 rewind 显式拒绝，不扩展 generation 迁移。

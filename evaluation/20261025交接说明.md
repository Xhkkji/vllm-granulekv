# 20261025 交接说明

> 范围：只记录最近的显存受限 KV、评分临时空间和 SolidAttention 对照进展。更早的优化历史请查对应验证报告。

## 1. 当前目标

512K 单卡路径虽然能完成一次 output=1 执行，但代价过高。当前转回 **128K 单卡单机**，先把正确性、资源预算与可比实验口径做扎实，再评估 CPU KV 外缓存相对 SSD-only 的实际价值。

本系统与 SolidAttention 属于同类的 SSD-backed sparse inference；本系统额外把 CPU DRAM 当作可复用 KV 外缓存。应在同一服务器上比较各路径，不拿不同设备的绝对吞吐直接比较。

## 3. 最近实现与证据

### 评分临时空间

本地未提交修改只作用于现有 `SolidAttentionPolicy._score_pages()` 的多 Query 评分：按 Query 分片计算原有分数，每片立即沿 Query 维归约，再合并最大值；stable Top-K、跨头 union、评分接口和选择算法不变。单张临时评分表目标上限为 256 MiB，不查询实时空闲显存，不增加同步或 CPU 往返。

- 形状估算：512K 时完整单张 FP16 score table 约 1.75 GiB，分片后单张约 224 MiB；这是由形状推算，不是进程峰值测量。
- 128K 的完整单张表约 448 MiB，按当前策略分片；实际 CUDA 峰值还包括 envelope 中间项和其他工作区。
- policy 测试在 root/MPS 环境报告 93 passed；CUDA 专项覆盖是否实际执行需确认，不能当作 CUDA 全面验收。
- 修改前后仅有 16K prefix / 16K suffix、output=1 的一次小对照，每版 1 次预热、3 次采样：TTFT 10.192s → 10.619s（+4.2%），含写回耗时 11.050s → 11.245s（+1.8%），评分耗时约 1.029s → 1.035s。未达到既定 5% 复测阈值；样本少，不足以证明有收益或稳定回退。
- 对照文件：`GranuleKV/vllm_evaluation/tutti_layerwise/result/20261025_score_workspace/comparison32.json`。

### 显存受限映射和 128K

- 128K 配置审计：Qwen2.5-7B-Instruct，GPU 每层 1024 slots（KV 区合计约 896 MiB），host 每层 8320 slots，4 个在途 request slots、1024 descriptor slots；128K full host KV 约 7.12 GiB。位置缓存扩展到 132096，没有修改模型 RoPE 配置。
- 128K 有界 no-prefix、output=1 回放检查通过：3584 个 Attention 检查，selection/KV fingerprint/Attention/logits/token 与 reference 对齐，记录的 owner、coverage、同步等错误计数为 0。
- 另有 128K restore/replay 三个点通过：64K/64K、127K/1K、128K/0；这是定向正确性证据，不是 128K 正式性能 sweep 或质量验收。
- 32K 有界映射的代表性正确性回放也通过。曾有一次因等待状态超时的失败尝试；后续有效版本通过，保留失败产物作追溯。
- 128K 证据目录：`GranuleKV/vllm_evaluation/tutti_layerwise/result/20261025_bounded_slots/`。

### 512K 成本与验证边界

- 修改评分临时空间后，无 prefix、output=1 单次运行完成，TTFT 约 **2255 秒（37.6 分钟）**，含写回约 2274 秒；进程从启动到清理约 2341 秒。
- 该次 validation 为 `off/not_run`，所以只证明执行走完，不证明数值正确性、质量或可比性能。
- 配置使用 GPU 10000 slots（约 8.54 GiB KV 区）和 host 32896 slots（约 28.1 GiB）。统计到约 14,308 次评分调用、评分约 250.6 秒、超过 1.15M 次 GPU slot eviction。总体开销不可接受，当前不继续 512K；回到 128K。
- 证据目录：`GranuleKV/vllm_evaluation/tutti_layerwise/result/20261025_score_workspace/after512k/`。

## 4. SolidAttention 论文口径

来源：[FAST ’26 论文](https://www.usenix.org/system/files/fast26-zheng.pdf)。CUDA 个人电脑配置为 RTX 4070 Laptop 8GB、64GB DDR5、1TB Samsung 990 PRO；host DRAM 使用限制为 16GB。模型为 Llama 3.2 3B、Llama 3.1 8B、Qwen 2.5 7B；权重 INT4、KV FP16；batch=1，最大输出 512。WikiText-2 prompt 截断到 1K–128K，性能图覆盖到 128K。block size=32 tokens；输入超过 4K 后 context budget=1K tokens，其中一半为 init/local、一半为 selected。论文的 10% sparsity 是 FlexGen baseline 设置，不是 SolidAttention 设置。LongBench 质量测试到 64K，不等同于 128K 质量验收。

SolidAttention 论文里的个人电脑结果只作文献锚点。服务器的 GPU、CPU、SSD、内存容量不同，不能把论文 token/s 或 speedup 当作本地直接 baseline。

## 5. 下一步建议

先冻结一个 128K、batch=1、单机单卡工作负载和各层预算；不要再跑 512K，也不扩成多点 sweep。测试分成两层：先用 output=1 做最小 correctness smoke；性能对照则所有系统必须使用相同 prompt、tokenizer、模型权重精度、KV 精度和生成长度。若要贴近 SolidAttention 的生成吞吐口径，再用相同的 512-token 输出长度；不要把 output=1 的结果与论文吞吐横向比较。

建议的最小系统对照：

| 组 | 路径 | 目的 |
| --- | --- | --- |
| A | SolidAttention（如能在同一服务器运行） | 外部 SSD sparse baseline；报告代码/模型/配置与论文的差别 |
| B | 本系统 SSD-only sparse | 固定本系统选择算法，关闭可复用 CPU KV 外缓存 |
| C | 本系统 CPU+SSD sparse | 与 B 配对，单独量出 CPU KV 层的增益和成本 |
| D | Dense SSD restore | 参考完整 KV 路径成本及正确性；不将其当作稀疏策略的唯一公平性能基线 |

B 与 C 是判断 CPU 外缓存价值的主比较；A 用来定位与已有系统的关系，D 作 Dense 参照。优先保证 B/C 使用完全相同的输入、GPU 容量、稀疏选择与 SSD 初始状态。若无法运行 SolidAttention 原实现，只能报告 SolidAttention-style 对照，明确算法和实现差异，不能称为论文复现。

现有 `B=16、budget=32` 与论文 `block=32、context budget=1K tokens` 不是同一名义配置。需要先按实际 Attention 保留 token 数、init/local/selected 分配和实际 H2D/SSD 字节核算对应关系；不能只对齐 block 数或沿用同一个“32”标签。论文原始新 prompt 测试与本系统 cached-prefix restore 也不是同一 workload；二者应分开报告，不混成一个性能数字。

每组至少记录 TTFT、生成耗时/吞吐、写回排空及含排空耗时、峰值 GPU/host 内存、SSD/H2D/D2H 字节、slot eviction、预测浪费和关键等待。报告一次资源匹配配置，明确 host DRAM 限额；若另测服务器全容量，单独列出，避免把资源规模优势说成算法收益。小样本只作初筛；验证配置尽量少，结论不能超出实际门禁。

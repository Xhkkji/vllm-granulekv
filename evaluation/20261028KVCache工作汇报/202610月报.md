工作主要内容
夏寒柯
1、CPU 外缓存与新增 KV 保存闭环。
围绕 SolidAttention-style 稀疏选择，引入 CPU 完整 KV backing：首窗初选数据从 SSD 直达 GPU，其余历史进入 CPU；后续计算优先复用 GPU 驻留数据，缺失的选中数据从 CPU 补取。新增 KV 经 GPU→CPU→SSD 保存，已有有效 SSD 副本继续复用，补齐“恢复、计算、保存、再次恢复”的链路。

2、数据组织与四层窗口调度。
完成 K/V 连续配对和 32 KiB 传输粒度改造，减少 I/O 描述与处理次数。参考 Tutti 的层级预取思路，将请求按四层窗口组织，目标是在计算当前窗口时准备下一窗口；保留逐层实际选择与缺失补取，四层逻辑调度不等同于四层连续物理传输。

3、固定显存工作集与长上下文验证。
解除完整逻辑历史必须常驻 GPU 的限制，支持受限容量下的逐层驻留与安全复用。128K 验证使用约 896 MiB GPU KV 区和 7.11 GiB CPU KV 区，无前缀建缓存回放完成 3584 次 Attention 检查并对齐，代表性缓存恢复用例通过。32K 小样本 Passkey 为 15/15；上述结果不等同于完整的 128K 长上下文质量验收。

4、端到端性能对照与瓶颈定位。
在 V100S 32GB、Qwen2.5-7B-Instruct、FP16、单卡单请求配置下，对比已有缓存前缀加 1K 新输入、输出 1 token 的恢复性能。写回对齐后的配对初测中，32K 首 token 延迟由 Dense 的 2183 ms 降至 Sparse 的 1208 ms，含排空由 2222 ms 降至 1811 ms；128K 分别由 8548 ms 降至 4357 ms、8788 ms 降至 5443 ms。最新预取补接后，Sparse 含排空为 32K 1581 ms、128K 5585 ms，长上下文下尚未体现额外收益。以上均为单次测量，资源和准备状态仍有差异，不能作为最终公平加速比。

5、512K 容量探索与临时空间优化。
保持选择规则不变，将评分分片计算并即时归约，512K 单张评分临时表的形状估算由约 1.75 GiB 降至 224 MiB。随后无前缀、输出 1 token 的运行完成，但首 token 耗时约 37.6 分钟，并出现大量 GPU 数据逐出。该次仅证明执行完成，未进行数值和质量验收，也不能与缓存前缀恢复直接比较。

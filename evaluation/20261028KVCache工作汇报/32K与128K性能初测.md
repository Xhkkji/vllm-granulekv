# 32K 与 128K KVCache 性能初测

数据日期：2026-10-26。以下为已有运行结果整理，没有重新测试。

## 性能表

单位：ms；每组无请求级预热、单次测量，output=1。

| 上下文 | Prefix / Suffix（tokens） | 路径 | TTFT | 首 token 后排空 | 含排空总耗时 |
| --- | --- | --- | ---: | ---: | ---: |
| 32K | 31744 / 1024 | Dense SSD→GPU | 1713.94 | 0.02 | 1713.96 |
| 32K | 31744 / 1024 | Sparse CPU+GPU | 1103.50 | 303.10 | 1406.60 |
| 128K | 130048 / 1024 | Dense SSD→GPU | 6423.96 | 0.03 | 6423.99 |
| 128K | 130048 / 1024 | Sparse CPU+GPU | 4390.42 | 1902.71 | 6293.13 |

TTFT 从请求提交计至首 token 返回；排空计至引擎跟踪的剩余任务结束，包括写回及其完成处理，不等同于纯 D2H 时间。output=1 时，总耗时为 TTFT 加尾部排空。

## 配置与链路

- 同服务器单卡，Qwen2.5-7B-Instruct，权重与 KV 均 FP16；batch=1，TP=PP=1，block=16 tokens，chunk=1024，28 层，eager / XFormers。
- 两条路径均使用四层逻辑窗口、lead=1、layer-barrier 推进；SSD descriptor 为 32 KiB。四层逻辑请求不代表跨层连续 DMA。
- Dense：完整 prefix 从 SSD 直达 GPU，8 个物理 layer regions 滚动复用；当前路径不持久化本次新增 KV。
- Sparse：首窗初选 block 直达 GPU，其余 prefix 送 CPU pinned backing；后续四层窗口完整读取到 CPU，逐层 actual selection 后补取缺失 KV 到 GPU。每头 block budget=32，再跨头 union；新增 KV 备份到 CPU，结束后复用已有 prefix 副本，仅保存新增完整 block。两次运行的预测 H2D block 计数均为 0。

| 上下文 | Dense 每 region slots / 物理 regions | Sparse 每层 slots / 物理层数 |
| --- | --- | --- |
| 32K | 2135 / 8 | 2135 / 28 |
| 128K | 8341 / 8（配置 override=8320，扩展后记录值） | 1024 / 28 |

## 比较边界与来源

- 这是 cached-prefix restore 初筛，不是从零处理整个 32K/128K prompt；缓存准备不计入表中时间。Sparse 运行前有 populate 和 metadata warmup，Dense 使用已有 SSD 数据，准备状态尚未对齐。
- Dense 未保存新增 KV，Sparse 有保存义务；两者物理 GPU 容量也不同。128K Dense 另记录到 28 次 legacy device synchronize，Sparse 为 0。因此不能把表中差值直接当作同资源、同完成义务下的正式加速比。
- 本次 validation=off，没有 Attention 数值回放验收；单次耗时和首 token 一致不足以证明完整正确性或质量。

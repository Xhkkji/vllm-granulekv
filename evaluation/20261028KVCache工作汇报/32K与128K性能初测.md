# 32K 与 128K KVCache 性能初测

数据日期：2026-10-26。以下为已有运行结果整理，没有重新测试。

## 性能表

单位：ms；每组无请求级预热、单次测量，output=1。

| 上下文 | Prefix / Suffix（tokens） | 路径 | TTFT | 首 token 后排空 | 含排空总耗时 |
| --- | --- | --- | ---: | ---: | ---: |
| 32K | 31744 / 1024 | Dense SSD→GPU | 1713.94 | 0.02 | 1713.96 |
| 32K | 31744 / 1024 | Sparse CPU+GPU | 1103.50 | 303.10 | 1406.60 |
| 128K | 130048 / 1024 | Dense SSD→GPU | 6423.96 | 0.03 | 6423.99 |
| 128K | 130048 / 1024 | Sparse CPU+GPU | 4390.42 | 1902.71 | 6293.13 |

TTFT 从请求提交计至首 token 返回；排空计至引擎跟踪的剩余任务结束，包括写回及其完成处理，不等同于纯 D2H 时间。output=1 时，总耗时为 TTFT 加尾部排空。

## 配置与链路

- 同服务器单卡，Qwen2.5-7B-Instruct，权重与 KV 均 FP16；batch=1，TP=PP=1，block=16 tokens，chunk=1024，28 层，eager / XFormers。
- 两条路径均使用四层逻辑窗口、lead=1、layer-barrier 推进；SSD descriptor 为 32 KiB。四层逻辑请求不代表跨层连续 DMA。
- Dense：完整 prefix 从 SSD 直达 GPU，8 个物理 layer regions 滚动复用；当前路径不持久化本次新增 KV。
- Sparse：首窗初选 block 直达 GPU，其余 prefix 送 CPU pinned backing；后续四层窗口完整读取到 CPU，逐层 actual selection 后补取缺失 KV 到 GPU。每头 block budget=32，再跨头 union；新增 KV 备份到 CPU，结束后复用已有 prefix 副本，仅保存新增完整 block。两次运行的预测 H2D block 计数均为 0。

| 上下文 | Dense 每 region slots / 物理 regions | Sparse 每层 slots / 物理层数 |
| --- | --- | --- |
| 32K | 2135 / 8 | 2135 / 28 |
| 128K | 8341 / 8（配置 override=8320，扩展后记录值） | 1024 / 28 |

## 比较边界与来源

- 这是 cached-prefix restore 初筛，不是从零处理整个 32K/128K prompt；缓存准备不计入表中时间。Sparse 运行前有 populate 和 metadata warmup，Dense 使用已有 SSD 数据，准备状态尚未对齐。
- Dense 未保存新增 KV，Sparse 有保存义务；两者物理 GPU 容量也不同。128K Dense 另记录到 28 次 legacy device synchronize，Sparse 为 0。因此不能把表中差值直接当作同资源、同完成义务下的正式加速比。
- 本次 validation=off，没有 Attention 数值回放验收；单次耗时和首 token 一致不足以证明完整正确性或质量。

原始结果位于 `GranuleKV/vllm_evaluation/tutti_layerwise/result/20261026_perf_compare/`，对应目录为：`32k_dense_ssd_31k1k`、`32k_sparse_cpu_gpu_current_v2`、`128k_dense_ssd_layerwise_current_v2`、`128k_sparse_cpu_gpu_current_v2`；表格取各目录 `summary.json` 的测量请求记录，不含 populate。

## 32K 新增 KV 写回对齐后（2026-10-26）

单位：ms；31744 prefix / 1024 suffix，output=1，无请求级预热，每组一次测量。

| 路径 | TTFT | 首 token 后排空 | 含排空总耗时 | D2H | SSD 写入 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dense SSD→GPU | 2183.35 | 39.09 | 2222.44 | 56 MiB | 56 MiB |
| Sparse CPU+GPU | 1208.14 | 602.47 | 1810.62 | 60.5 MiB | 56 MiB |

- 沿用上述模型、精度、block=16、chunk=1024、window=4、lead=1；GPU slots 均为 2135，Dense 为 8 个物理 regions，Sparse 为 28 层独立区域；host 每层 2304 slots，Sparse 每头 budget=32。
- Dense 历史读取仅 SSD→GPU（1736 MiB），历史 SSD→CPU 和 H2D 均为零；新增/修改 KV 与 Sparse 一样走 GPU→CPU pinned backing→SSD。两边均保存新增 64 个完整 block、复用 1984 个 clean prefix block，1792 个 layer-block 的 SSD 回读全部一致，最终写回 backlog 为零。
- Sparse TTFT 降低 44.7%，含排空耗时降低 18.5%。排空包含剩余传输、轮询、元数据处理与提交；Sparse 仍有页面代表元数据登记开销。结果含 CPU 快照校验，两边 GPU 容量及准备状态仍有差异，单次测量不作为最终公平加速比；未做完整 Attention/logits 回放。

来源：`GranuleKV/vllm_evaluation/tutti_layerwise/result/20261026_dense_writeback/` 下 `dense32_readback/run_1/summary.json` 和 `sparse32_prepared_readback/run_1/summary.json`。

## 128K 新增 KV 写回对齐后（2026-10-26）

单位：ms；130048 prefix / 1024 suffix，output=1，无请求级预热，每组一次测量，不含缓存准备。

| 路径 | TTFT | 首 token 后排空 | 含排空总耗时 | D2H | SSD 写入 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Dense SSD→GPU | 8548.28 | 239.82 | 8788.10 | 56 MiB | 56 MiB |
| Sparse CPU+GPU | 4357.10 | 1086.32 | 5443.42 | 60.5 MiB | 56 MiB |

- 沿用上述单卡 Qwen2.5-7B-Instruct、FP16 权重/KV、block=16、chunk=1024、window=4、lead=1；max_model_len=132096，GPU memory utilization=0.80。Dense 每 region 实际 8341 slots（override=8320）、8 个物理 regions；Sparse 每层 1024 slots、28 层独立区域、每头 budget=32；host 均为每层 8320 slots。
- Dense 历史仅 SSD→GPU（7112 MiB），历史 SSD→CPU 和 H2D 均为零；Sparse 为 SSD→GPU 4.5 MiB、SSD→CPU 7107.5 MiB、H2D 336.91 MiB。两边新增/修改 KV 均走 GPU→CPU pinned backing→SSD，保存新增 64 个完整 block、复用 8128 个 clean prefix block；1792 个 layer-block 的 SSD 回读全部一致，写回 backlog 为零。
- Sparse TTFT 降低 49.0%，含排空耗时降低 38.1%。Sparse 保存后仍全量重建 8192 blocks × 28 层的页面元数据；观察到 SSD READY 至引擎完成事件约 1000 ms，尚未独立计时拆分。预测 H2D block 计数仍为零，不能归因为四层预测充分重叠。
- 结果含 CPU 快照校验；Sparse 有 populate 和 metadata warmup，Dense 使用其准备的 SSD prefix，两边 GPU 容量及准备状态有差异。单次测量不作为最终公平加速比；validation=off，SSD 回读通过不等同于完整 Attention/logits 或质量验收。

来源：`GranuleKV/vllm_evaluation/tutti_layerwise/result/20261026_dense_writeback/` 下 `dense128_readback/run_1/summary.json` 和 `sparse128_prepared_readback/run_1/summary.json`。

## Sparse 窗口预测 H2D 补接后（2026-10-26）

| 上下文 | Sparse 版本 | TTFT | 首 token 后排空 | 含排空总耗时 |
| --- | --- | ---: | ---: | ---: |
| 32K | 修复前 | 1208.14 | 602.47 | 1810.62 |

| 128K | 修复前 | 4357.10 | 1086.32 | 5443.42 |

- 配置：Qwen2.5-7B-Instruct，FP16 权重/KV，batch=TP=PP=1，block=16、chunk=1024、每头 budget=32、window=4、lead=1。32K 为 31744/1024 prefix/suffix，GPU 每层 2135 slots、host 每层 2304 slots；128K 为 130048/1024，GPU 每层 1024 slots、host 每层 8320 slots。
- 链路不变：首窗初选 SSD→GPU，其余历史按四层窗口完整 SSD→CPU backing；预测及 actual miss 复用逐层 H2D，新增 KV 经 CPU 写回 SSD。本次补接 host READY 后的预测预取。
- 32K TTFT 降低 3.9%、含排空降低 12.7%；预测 H2D 为 144 个 layer-block，其中 43 个被 actual 使用、101 个未使用，额外 H2D 为 3.16 MiB。128K TTFT 增加 0.8%、含排空增加 2.6%，预测 H2D 仍为零，尚未获得预测预取收益。
- 两点首 token 与修复前一致，均保存新增 64 个完整 block，1792 个 layer-block 的 SSD 回读全部匹配，记录的传输/owner/覆盖错误及最终写回 backlog 为零。validation=off，未做完整 Attention/logits 回放；单次对照不能证明稳定收益或将全部差值归因于本次修复。

来源：`GranuleKV/vllm_evaluation/tutti_layerwise/result/20261026_window_h2d_compare/` 下 `sparse32/run_1/summary.json` 和 `sparse128/run_1/summary.json`；修复前沿用上一节对应 Sparse 结果。

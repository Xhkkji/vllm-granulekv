### 第一阶段：唯一读集与 metadata

- 继续使用 `history_blocks + attention`：完整历史参与原 selector，init/local 与旧 partial tail 规则不变，当前 chunk 按原因果语义计算。
- `_restore_live_backing()` 在目标路径只保护写前 partial tail；`_correct_hierarchical_layer()` 仅恢复实际选中历史。生成历史不再整段恢复，也不从 host 重读当前 chunk。
- 复用 page-scoped GPU representatives。请求私有封块 metadata 与共享 prefix 隔离。feedback 仅在候选、预算、Query 语义一致时复用；边界不同仍保留原 predictor。
- 复用现有 validation，为每笔 H2D 记录 actual、partial_tail 或 prefetch 来源、历史长度、逻辑源和物理目标。actual 必须属于本次历史读集，partial_tail 必须是写前旧尾块，prefetch 仅限已有完整 immutable prefix。
- 同请求同层同逻辑 block 按有效 token 数区分版本，重复 H2D 单独计数。预测多搬与同版本重复搬运不是同一指标。

### 第二阶段：28 层独立最终 KV

- 在 `get_layer_working_set_regions()` 的既有 host-backing 路径返回模型层数，其余配置继续校验；其他路径不改。
- 现有 allocation、connector、worker 均消费同一个 region 数，因此 28 层绑定 28 份最终 Attention KV。无需新增 scatter、slot allocator 或 owner key。
- `window=4` 仍控制预取窗口，不再将最终 KV 限制为 8 个跨层共享 region。
- 实际每层 2135 slots、每 slot 32768 bytes，GPU KV 容量由 8-region 的约 0.521 GiB 增至 28-region 的约 1.824 GiB。不能把这一阶段的全部收益归为同容量调度优化。
- release 和 D2H 完成不清除有效 GPU owner；真实覆盖、版本变化及请求结束仍按原 owner/fence 处理。

### 第三阶段：提前提交与消费依赖

- `copy_host_blocks_to_gpu_async()` 只提交并返回 event；`_consume_host_copies()` 仅对实际消费的 pending copy 安装 compute wait，并批量发布 owner。actual 和 prefetch 共用 copy 实现。
- forward 完成后把已有 feedback 写回已有 correction plan。当前层 correction 完成、Attention 尚未启动时，`_prefetch_next_layer()` 尝试下一层 immutable 预测集合。
- 仅提交 host READY、GPU miss、无匹配 pending 的完整历史 block。预测路径不等待未就绪 host，也不新增 SSD correction。
- H2D 先于本层 release 后的 D2H 入同一 copy stream；dirty backing 仍完整保留。已有 deferred WRITE 在入口让待推进 READ 优先，不新增写回队列或线程。
- finish/abort 清理补齐未消费 pending copy 的物理 owner；在途 DMA 仍保护 host 源，直到 event 完成才释放。没有新增 epoch 状态机或 rewind 支持。

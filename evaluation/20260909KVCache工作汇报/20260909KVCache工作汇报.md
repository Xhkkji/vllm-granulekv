# KV Cache 工作汇报

时间范围：2026.08.27 - 2026.09.08

---

## 第 1 页：本期工作概览

本期主要完成两件事：

1. 收束 GranuleKV 的底层接口和请求生命周期，使其从多条实验路径收敛为统一、稳定的 GPU-SSD 异步 I/O 底座。
2. 以 Quest 为基础搭建稀疏注意力的通用接口，将稀疏 KV 选择与 GranuleKV I/O、vLLM 调度和 attention consumer 解耦。

当前状态：GranuleKV 底层接口已基本稳定，Quest 稀疏注意力已完成第一版通用接入和基础链路验证。

---

## 第 2 页：GranuleKV：从多条实验路径到统一接口

### 收束前

1. 同时存在 staged、legacy、异步预取等多条调用路径。
2. 上层调度逻辑与底层 I/O 协议耦合较深，需要感知 slot、JSON、CUDA IPC 等细节。
3. logical transfer 与底层 descriptor 提交边界不清晰，层级预取、同步/异步路径各自维护接口。
4. 实验代码依赖具体实现细节，难以切换上层策略。

### 收束后

1. 统一为 GranuleKV Client 的 allocation、start、submit、status、wait、complete 生命周期。
2. 通过统一 request handle 和 protocol 屏蔽底层控制细节。
3. 分离 logical request、descriptor pool 和 native progress，支持完成即回收、持续 refill。
4. vLLM 的 layer-wise restore、prefetch 和回归实验统一走 GranuleKV 请求接口，GranuleKV 作为独立 I/O backend 供上层策略复用。

### 本期完成

1. 清理跨进程 staged 计划状态和无引用的旧包装接口。
2. 统一 client、service、executor 三层请求生命周期。
3. 固化 resident daemon、request slot、logical transfer 和 descriptor refill 机制。
4. 完成 MPS 环境下的接口重构回归和 layer-wise 同步/异步 smoke 验证。

## 第 3 页：Quest 基础上的稀疏注意力通用接口

本期以 Quest 为基础，搭建了与具体稀疏算法解耦的 `SparseKVPolicy` 通用接口，使稀疏选择、KV 恢复和 attention 计算可以分开实现。

### 接口流程

1. 根据 query 和 KV 元数据选择本轮需要的逻辑 KV block。
2. 将选中的逻辑 block 与 vLLM 现有的物理 KV block 建立对应关系。
3. 由 GranuleKV 负责恢复所需 KV，attention 使用恢复后的 block 完成计算。

### 本期完成

1. 定义了可插拔的 `SparseKVPolicy` 接口，为后续接入不同稀疏策略保留统一入口。
2. 完成了稀疏 block 选择、现有 KV block 映射和 attention 消费之间的基本衔接。
3. 将 Quest 作为首个策略接入，并完成 vLLM/GranuleKV 基础链路验证。

### 当前边界

1. 当前已经具备“稀疏选择 - KV 恢复 - attention 消费”的基本通用接口。
2. 更完整的动态 SSD 恢复选择和多请求联合调度属于下一阶段工作。

## 总结

GranuleKV 已从多条耦合的实验实现，收束为可复用的统一 GPU-SSD 异步 I/O 底座；在此基础上，稀疏注意力也已形成独立的策略接口，并完成 Quest 的第一版接入，为后续比较不同稀疏策略和 I/O 调度策略做好了基础。
